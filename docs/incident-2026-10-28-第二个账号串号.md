# 事故记录 2026-10-28 · 添加第二个账号却刷新了第一个的凭证

> 状态：**已修复并验证**（插件 0.3.12 / magpie 已重启）
> 待办：本文件内容等 Hindsight 后端（192.168.1.6:8888）恢复后灌入记忆库

## 症状

在 magpie 里点「添加新账号」：

- 第一次：正常，成功加进账号 A
- 第二次：**不开窗口，一秒内就成功**，但 magpie 里没多出账号，A 的凭证被刷新了

## 根因

不是仓库代码的问题 —— **magpie 里装的插件版本太老（0.3.5）**。

| 事实 | 证据 |
|---|---|
| magpie 加载的是 Magicrew 0.3.5 | `~/.config/magpie/plugins/node_modules/Magicrew/package.json` version=0.3.5；`bun.lock` 锁 `#825416b` |
| 0.3.5 用**固定复用 profile** | 0.3.5 `src/browser-login.mjs:25` → `join(homedir(), ".cache", "magpie", "magicrew-login-profile")`，注释原文「profile 目录**不删**，下次还能复用登录态」 |
| 该目录里躺着上一个账号的凭据 | 读 `.../magicrew-login-profile/Default/Local Storage/leveldb` → origin `www.letsmagic.cn`，org=`66p0q56qo47j` |
| 第二次打开时立刻被判「已登录」 | 同一 profile → `waitForCreds` 第一轮（1.5 s）就读到残留 → 判定成功 → 关窗 |
| magpie 侧按同身份处理 → 替换而非新增 | `providers-state.json` 的 `accountNames` 只有 `h97gkbu8bruj` 一条 |

链路：**复用 profile 残留凭据 → 立刻判成功 → 提交同 uid → magpie 替换旧账号 → 用户看到「直接刷新凭证」**。

## 代码里早在 0.3.6 就修了（提交 6ca3255）

- `newProfileDir()`：每次登录一个新目录，结束即删
- `sweepProfiles()`：清残留，且**必删**历史复用目录 `magicrew-login-profile`
- `waitForCreds(…, { baseline })`：窗口打开时就存在的凭据不算登录成功
- `~/.cache/magpie/magicrew-orgs-<site>.json`：加过的 org 名单，挡住「本机浏览器里那把属于已加过账号」时仍自动接上

## 这次做了什么

```bash
# 1. 备份 magpie 插件清单（可回滚）
cd ~/.config/magpie/plugins
cp package.json package.json.bak-before-magicrew-012-20261028-003807
cp bun.lock    bun.lock.bak-before-magicrew-012-20261028-003807

# 2. 升级（关键：plugin add 不重解析 commit，必须 update）
cd /e/Downloads && ./magpie-windows-amd64.exe plugin update     # → Magicrew 0.3.12

# 4. 预灌已知 org 名单（本机真实 Edge 里也有 h97gkbu8bruj 的登录态，不挡会被自动接上）
```

## 验证结果

- `magpie plugin list` → `(Magicrew 0.3.12)`，账号仍在：`h97gkbu8bruj`（超级麦吉）、`1451895195@qq.com`（MagiCrew）
- `bun.lock` → `Magicrew@github:MYCF711/magpie-magicrew-auth#970a3ea`
- `readLocalCreds("www.letsmagic.cn").org = h97gkbu8bruj`，在 `readKnownOrgs("magicrew")` 里 → **点添加不会再自动接上旧账号**
- 模型列表已重新拉取：国内 27 / 国际 49

## 三条可复用判据

1. **`magpie plugin add <git-url>` 不会升级已装插件** —— bun.lock 锁着 `#<sha>`，add 只是确认依赖存在；升级必须 `magpie plugin update`。
2. **`~/.cache/magpie/plugin-host/*.js` 没生成新文件 = 插件代码没重载** —— 改完必须重启 magpie 进程。
3. **一次性 profile 的代价要讲清楚**：独立 user-data-dir 没有日常浏览器的 cookie，所以每次「添加账号」都要在弹窗里重登一次；只有「本机浏览器里登好的、且不在 orgs 名单里的」才会自动接上。
