# 排查手册：登录「超级麦吉」报 `账号不存在`

适用：在 magpie 里装 `magpie-magicrew-auth`，用**手机号 + 密码**登录，返回

```
登录未完成
the sign-in failed: 账号不存在
```

请照第 1→2→3 步走一遍，然后把第 4 节的报告模板填好发回来。全程约 5 分钟，不需要改任何代码。

---

## 第 0 步 · 先明确一件事：`账号不存在` 跟密码无关

上游源码 `dtyq/magic`（master）`backend/magic-service/app/Application/Authentication/Service/LoginAppService.php`：

```php
private function verifyPhoneAccount(CheckLoginRequest $request): AccountEntity
{
    $account = $this->authenticationRepository->findAccountByPhone(
        $request->getStateCode(),   // ← 区号
        $request->getPhone()
    );
    if (! $account) {
        ExceptionBuilder::throw(AuthenticationErrorCode::AccountNotFound);  // 33002 账号不存在
    }
    if (! $this->passwordService->verifyPassword($request->getPassword(), $account->getPassword())) {
        ExceptionBuilder::throw(AuthenticationErrorCode::PasswordError);    // 33003 密码错误
    }
    return $account;
}
```

**只有 `(区号, 手机号)` 查不到账号时才会报 33002。密码错会报 33003。**

所以「账号不存在」= 这个号码组合在**登录账号表**里没有，不是密码打错了。

另一个细节（`LoginApi.php`）：

```php
$stateCode = str_replace('+', '', $request->input('state_code', ''));   // ★ 登录时把 + 削掉
```

⇒ 传 `+86` 和 `86` 发送到服务端后完全一样，会一起变成 `86`。所以「区号格式」这件事只能从数据库存的写法上找差异，不能靠改 `+` 来试。

---

## 第 1 步 · 自检：你的账号有没有「密码」

如果你这个号是**微信 / 苹果扫码**注册的，很可能从来没设过密码。那样 `phone_password` 必然失败。

打开 https://www.letsmagic.cn/login ，点「密码登录」，填你自己的手机号 + 密码：

| 你看到的 | 说明 | 下一步 |
|---|---|---|
| **能登进去** | 号码和密码都对 | 问题在插件传参，走第 2 步 |
| **密码错误** | 号码对，只是这个密码不对 | 换个记得的密码重试；确认后走第 2 步 |
| **账号不存在** | 这个号的「密码登录记录」不存在 | 去「账号安全」设一次密码，再回来 |
| 页面没有「密码登录」入口 | 该站点只支持扫码 | 见第 3 节的「兜底方案」 |

## 第 2 步 · 三步定位（脚本）

把下面这段存成 `probe.mjs`，**只改两处**：`PHONE`（你的完整手机号）和 `PASSWORD`（你的密码）。然后 `node probe.mjs`。

```js
// probe.mjs —— 只读诊断，不会改你的账号
import { readFileSync, readdirSync } from "node:fs"
import { homedir, platform } from "node:os"
import { join } from "node:path"

const PHONE = "13800138000"      // ← 改成你的完整手机号（不带 +86）
const PASSWORD = "你的密码"        // ← 改成你的密码
const HOST = "https://i-magic-service.letsmagic.cn"
const SITE_KEYWORD = "letsmagic"

// ── 1. 从本机浏览器抠登录态（用来验证「账号存在但 phone 为空」这一支）
// 这个只能证明账号存在，不能替代手机号登录失败本身
const profiles = []
if (platform() === "win32") {
  const base = join(homedir(), "AppData")
  profiles.push(join(base, "Local/Microsoft/Edge/User Data/Default/Local Storage/leveldb"))
  profiles.push(join(base, "Local/Google/Chrome/User Data/Default/Local Storage/leveldb"))
  profiles.push(join(base, "Roaming/Mozilla/Firefox/Profiles"))
} else if (platform() === "darwin") {
  profiles.push(join(homedir(), "Library/Application Support/Microsoft Edge/Default/Local Storage/leveldb"))
  profiles.push(join(homedir(), "Library/Application Support/Google/Chrome/Default/Local Storage/leveldb"))
}

let jwt = "", org = "", best = 0
for (const dir of profiles) {
  let files = []
  try { files = readdirSync(dir) } catch { continue }
  for (const f of files) {
    let d; try { d = readFileSync(join(dir, f)) } catch { continue }
    const s = d.toString("latin1")
    if (!s.includes(SITE_KEYWORD)) continue
    for (const m of s.matchAll(/"key":"authorization","value":"([^"]+)"/g)) {
      const t = m[1]; let i = 0
      try { i = JSON.parse(Buffer.from(t.split(".")[1], "base64").toString()).iat || 0 } catch {}
      if (i >= best) { best = i; jwt = t }
    }
    for (const m of s.matchAll(/"key":"organizationCode2?","value":"([^"]*)"/g)) if (m[1]) org = m[1]
  }
}
console.log("① 浏览器登录态：", jwt ? `找到了（${jwt.length} 字符）` : "没找到 —— 请先在浏览器里登录过该站点")

// ── 2. 区号枚举（验「state_code 写法不一致」）
console.log("\n② 手机号登录探针（密码故意用错的，只看错误码）：")
for (const sc of ["86", "0086", "00086", "", "CN"]) {
  const r = await fetch(HOST + "/api/v1/sessions", {
    method: "POST",
    headers: { "content-type": "application/json", "user-agent": "Mozilla/5.0" },
    body: JSON.stringify({ type: "phone_password", phone: PHONE, password: "__definitely_wrong__", state_code: sc }),
  })
  const t = await r.text()
  console.log(`   state_code=${JSON.stringify(sc).padEnd(9)} → ${t.slice(0, 100)}`)
}

// ── 3. 空邮箱探针（验「account.phone 为空、email 为空串」）
console.log("\n③ 空邮箱探针：")
const r3 = await fetch(HOST + "/api/v1/sessions", {
  method: "POST",
  headers: { "content-type": "application/json", "user-agent": "Mozilla/5.0" },
  body: JSON.stringify({ type: "email_password", email: "", password: PASSWORD }),
})
console.log("   email=\"\" + 你的密码 →", (await r3.text()).slice(0, 200))

// ── 4. 账号档案（看这个号在你组织里的真实区号/手机号打码）
if (jwt) {
  const r4 = await fetch(HOST + "/api/v1/contact/accounts/me/users", {
    headers: { authorization: "Bearer " + jwt, "organization-code": org, "content-type": "application/json" },
  })
  console.log("\n④ 账号档案：", (await r4.text()).slice(0, 400))
}
```

## 第 3 步 · 结果怎么读

| 你看到的结果 | 结论 | 怎么办 |
|---|---|---|
| ② 里某一行返回 **33003 密码错误** | 号码在对的表里，只是**区号写法**和插件传的不一样 | 记下那个 `state_code`，报给维护者；插件传参要改成该写法 |
| ② 全部 **33002**，但 ④ 里 `phone` 有值 | 账号有手机号，但**登录账号表里没有**（手机号只写在用户档案表） | 去站点「账号安全」补设一次密码/绑定手机号；这是服务端注册流程的问题 |
| ② 全部 33002，且 ④ 里 `phone` 为空 | 这个号在档案里都没有手机号 | 说明注册用的是扫码/邮箱，手机号登录不适用 |
| ③ 返回 **`code:1000`** | 你的账号 `email` 是空串、密码就是这个 | 可以先用「粘贴 JWT」方式登录（见下），并把结果报上来 |
| ③ 返回 **33003** | 账号的 `email` 是空串（能命中），但密码不是这个 | 密码记错了；或者这个号从没设过密码 |
| ③ 返回 **33002** | `email=""` 命不中 | 你的账号 email 不是空串，这条例外，把 ④ 的档案贴上来 |

### 兜底方案：先用「粘贴 JWT」跑起来

不管上面查出什么，这条路现在就能用：

1. 浏览器登录 https://www.letsmagic.cn
2. F12 → Application → Local Storage → `https://www.letsmagic.cn`
3. 找到 `MAGIC:user:authorization`，复制它的值里 `"value":"..."` 中间那一整串（`eyJ` 开头）
4. magpie 里选「超级麦吉 登录态（JWT）」这个登录方式，粘贴进去

有效期 30 天，期间插件会自动续期，不用重来。

## 附 · 为什么值得试「空邮箱」

我这台机器上的样本（`phone` 打码 `189****051`、`country_code` `+86`、`email` 为 null）：

```
POST /api/v1/sessions {type:"email_password", email:"", password:""}     → 33003 密码错误
POST /api/v1/sessions {type:"email_password", email:"x@example.com", …}  → 33002 账号不存在
POST /api/v1/sessions {type:"phone_password", phone:"<该号>", …}          → 33002 账号不存在
```

`email=""` 能命中、`phone` 命中不了 —— 这是「登录账号表里 email 为空串、phone 没写进去」的典型形状。
如果你那边也是这个形状，那就是同一个问题，不是你的号码填错了。
